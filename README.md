# RAG-чатбот по документам

Чатбот, который отвечает на вопросы по загруженным файлам — PDF, DOCX и TXT. Это не обёртка над ChatGPT, а полноценная RAG-система: документ сначала читается, режется на куски, каждый кусок превращается в вектор, а на вопрос модель отвечает только по найденным фрагментам, указывая, где именно нашла ответ.

Хочешь проверить — скажи боту «сколько длится отпуск в вашей компании» после того, как загрузишь свой трудовой договор. Он найдёт нужный абзац и ответит со ссылкой на страницу.

---

## Что умеет

- Загрузка файлов прямо в браузере: PDF, DOCX, TXT. Можно несколько сразу.
- Разбивка текста на чанки, превращение в векторы, хранение в векторной базе ChromaDB.
- Поиск релевантных фрагментов под каждый вопрос и ответ по ним.
- В ответе — источники: номер страницы или абзаца, откуда взят ответ.
- Помнит историю диалога, так что можно уточнять вопросы («а если год?»).
- Нормальная обработка ошибок: битый PDF, пустой файл, защищённый паролем, неподдерживаемый формат — всё это не роняет программу, а показывает понятное сообщение.

## Стек

- **Python 3.10+**
- **Streamlit** — веб-интерфейс
- **LangChain** — оркестрация RAG-пайплайна
- **ChromaDB** — векторная база, сохраняется в папку `db/`
- **pypdf / python-docx** — чтение PDF и DOCX
- Модель — на выбор:
  - **Любой OpenAI-совместимый API** (OpenAI, Groq, OpenRouter, DeepSeek, Jina и т.п.) через один конфиг;
  - **Ollama** — локально и бесплатно, без ключей и без интернета после первого скачивания модели.

## Как это работает под капотом

Если коротко, пайплайн такой:

1. Ты загружаешь файл. Программа пишет его в `uploads/` и проверяет: формат, размер, не пустой ли, не зашифрован ли PDF, есть ли вообще текст (вдруг это сканы).
2. Текст режется на чанки по ~900 символов с перекрытием 120 символов. Перекрытие нужно, чтобы при разрезе не потерялась мысль, которая тянется через границу куска. Каждый чанк хранит метку источника — номер страницы или абзаца.
3. Каждый чанк превращается в вектор (эмбеддинг) и кладётся в ChromaDB.
4. На твой вопрос текст тоже превращается в вектор и сравнивается с базой. Возвращается несколько самых похожих кусков.
5. Эти куски подставляются в промпт вместе с историей диалога. Модель отвечает только по ним и ставит номера источников `[1]`, `[2]`.
6. Под ответом выводится список источников с привязкой к файлу и странице.

Весь код лежит в папке `rag/` и не зависит от интерфейса — ту же логику можно переиспользовать из командной строки или API.

```

├── rag/                    # RAG-логика
│   ├── loaders.py          # чтение PDF/DOCX/TXT + проверка ошибок
│   ├── chunking.py         # разбивка на чанки с перекрытием
│   ├── embeddings.py       # выбор модели эмбеддингов и генерации
│   ├── store.py            # работа с ChromaDB
│   └── chat.py             # поиск + генерация ответа с источниками
├── tests_smoke.py          # быстрая проверка ядра без модели
├── db/                     # создаётся при первом запуске (векторная база)
└── uploads/                # создаётся при первом запуске (загруженные файлы)
```

## Как запустить

Проект рассчитан на то, что его можно поднять бесплатно и локально. Для этого нужен Python и Ollama (локальный сервер моделей). OpenAI — опционально, если хочется отвечать через GPT.

### Общая подготовка

Нужен Python версии **3.10 или новее**.

Открой терминал и перейди в папку проекта:

```bash
cd путь/до/Rag-chatbot_docs
```

Создай виртуальное окружение (чтобы зависимости не засоряли систему) и включи его.

**Windows (PowerShell):**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

Если PowerShell ругается на выполнение скриптов, выполни сначала:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

**macOS / Linux (терминал):**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Теперь поставь зависимости:

```bash
pip install -r requirements.txt
```

На Windows командой может быть `pip3` или `py -m pip` — зависит от того, как установлен Python. Если `pip` не находится, попробуй `python -m pip install -r requirements.txt`.

### Шаг 1. Локальная модель (Ollama) — бесплатный путь

Это рекомендация по умолчанию: ничего не стоит, ключи не нужны.

1. Скачай и установи Ollama: https://ollama.com/download (есть и для Windows, и для macOS). После установки сервер обычно стартует сам и живёт в фоне.
2. Убедись, что сервер работает: открой терминал и выполни
   ```bash
   ollama list
   ```
   Если команда нашлась и ничего не упало — ок.
3. Скачай две модели — одну для генерации ответов, вторую для векторов:
   ```bash
   ollama pull llama3.2
   ollama pull nomic-embed-text
   ```
   Первое скачивание займёт пару минут. Дальше модели живут локально, интернет не нужен.

На macOS, если ставил через Homebrew (`brew install ollama`), сервер сам не запускается — запусти его в отдельном терминале командой `ollama serve` и оставь открытым.

### Шаг 2. Настройки

Скопируй шаблон в `.env`:

**Windows:**

```powershell
copy .env.example .env
```

**macOS / Linux:**

```bash
cp .env.example .env
```

Открой `.env` любым редактором. По умолчанию там уже стоит `LLM_PROVIDER=ollama`, то есть ничего менять не нужно — всё заработает на локальной модели. Просто проверь, что имена моделей совпадают с теми, что ты скачал в шаге 1 (`llama3.2` и `nomic-embed-text`).

Хочешь отвечать через GPT вместо локальной модели — поменяй в `.env`:

```
LLM_PROVIDER=openai
OPENAI_API_KEY=sk-твой-ключ
```

### Бесплатные OpenAI-совместимые API (без скачивания)

Если ставить локальную модель не хочется, а платить за OpenAI — тем более, есть вариант вообще без установки моделей: бесплатные API с OpenAI-совместимым форматом. Работает это так: генерация ответов идёт через один сервис, а векторы — через другой (они могут не совпадать). Ниже готовый рабочий вариант на бесплатных лимитах.

1. **Генерация — Groq** (https://console.groq.com). Регистрация, бесплатный ключ вида `gsk_...`. Без карты. Модель для ответов — `llama-3.3-70b-versatile`.
2. **Эмбеддинги — Jina AI** (https://jina.ai/embeddings). Бесплатный ключ вида `jina_...`, к нему даётся пакет токенов. Модель — `jina-embeddings-v3` (хорошо понимает русский).

Дальше в `.env` укажи оба сервиса:

```
LLM_PROVIDER=openai
LLM_API_KEY=gsk_твой_ключ_groq
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=llama-3.3-70b-versatile

EMBEDDING_API_KEY=jina_твой_ключ
EMBEDDING_BASE_URL=https://api.jina.ai/v1
EMBEDDING_MODEL=jina-embeddings-v3
```

Альтернативы для генерации вместо Groq (тоже OpenAI-совместимы, меняешь только `LLM_*`):

- **OpenRouter** — https://openrouter.ai, десятки бесплатных моделей с суффиксом `:free`, включая DeepSeek. Базовый URL `https://openrouter.ai/api/v1`.
- **DeepSeek** — https://platform.deepseek.com, базовый URL `https://api.deepseek.com`, модель `deepseek-chat`.
- **GitHub Models** — бесплатный доступ к GPT-4o и другим по OpenAI-совместимому API.

Если хочешь использовать один и тот же ключ и сервис и для генерации, и для векторов — достаточно `OPENAI_API_KEY`, а `LLM_BASE_URL` / `EMBEDDING_BASE_URL` можно не заполнять (по умолчанию — `api.openai.com`).

### Шаг 3. Запуск

```bash
streamlit run app.py
```

В терминале появится адрес — обычно `http://localhost:8501`. Открой его в браузере.

Слева загрузи файлы (можно сразу несколько), нажми «Индексировать загруженные» и жди. Потом просто пиши вопросы в поле внизу. Ответ придёт с источниками — на что модель опиралась, на той странице и искала.

Останавливается программа, как и любой процесс в терминале: сочетание `Ctrl+C`.

### Быстрая проверка ядра без модели

Если хочется убедиться, что чтение файлов, чанкинг и база работают, не поднимая Ollama:

```bash
pip install -r requirements-dev.txt
python tests_smoke.py
```

Тест создаёт временные PDF/DOCX/TXT, проверяет, что битый и зашифрованный файлы корректно отбрасываются, гоняет разбивку на чанки и векторную базу. Модель не нужна — используются фиктивные векторы.

## Что можно настроить

Всё через файл `.env`:

| Переменная | За что отвечает | По умолчанию |
| --- | --- | --- |
| `LLM_PROVIDER` | `ollama` или `openai` | `ollama` |
| `OPENAI_API_KEY` | ключ (OpenAI или любого совместимого API) | пусто |
| `OPENAI_MODEL` | модель генерации | `gpt-4o-mini` |
| `OPENAI_EMBEDDING_MODEL` | модель векторов | `text-embedding-3-small` |
| `LLM_API_KEY` | отдельный ключ для генерации (если отличен от `OPENAI_API_KEY`) | = `OPENAI_API_KEY` |
| `LLM_BASE_URL` | адрес API для генерации (Groq/OpenRouter/DeepSeek и т.п.) | пусто (OpenAI) |
| `LLM_MODEL` | модель генерации для выбранного API | = `OPENAI_MODEL` |
| `EMBEDDING_API_KEY` | отдельный ключ для векторов (например, Jina) | = `OPENAI_API_KEY` |
| `EMBEDDING_BASE_URL` | адрес API для векторов | = `LLM_BASE_URL` |
| `EMBEDDING_MODEL` | модель векторов для выбранного API | = `OPENAI_EMBEDDING_MODEL` |
| `OLLAMA_MODEL` | модель генерации (Ollama) | `llama3.2` |
| `OLLAMA_EMBEDDING_MODEL` | модель векторов (Ollama) | `nomic-embed-text` |
| `OLLAMA_BASE_URL` | адрес локального сервера | `http://localhost:11434` |
| `CHUNK_SIZE` | размер чанка в символах | `900` |
| `CHUNK_OVERLAP` | перекрытие между чанками | `120` |
| `TOP_K` | сколько фрагментов подаём модели | `4` |
| `TEMPERATURE` | температура генерации (0 — строго) | `0.2` |

## Типовые проблемы

- **«Failed to connect to Ollama»** — сервер Ollama не запущен, либо не совпадает адрес. Запусти `ollama list` и проверь. На macOS после `brew install` запусти `ollama serve`.
- **«В PDF не найден текст»** — это сканы без текстового слоя. Нужен OCR, я его в этой версии не делаю.
- **«PDF защищён паролем»** — так и есть, такой файл не открыть без пароля.
- **Очень длинные ответы или путаница** — уменьши `TOP_K` или подними `CHUNK_SIZE`. Для коротких документов хватает значений по умолчанию.
- **Кириллица превращается в кракозябры в TXT** — файл в нестандартной кодировке. Поддержаны UTF-8 и cp1251; другие кодировки лучше пересохранить.

## Ограничения

- Не делает OCR: PDF со сканами без текстового слоя не индексирует (см. выше).
- Хранит всё в одной коллекции — то есть это «одна база знаний», а не много отдельных. Для демо и внутреннего использования этого достаточно.
- Не различает, кто загружает файлы: в базе общие для всех документы.

## Чего можно добавить

Если смотреть проект шире, логично вырастить из него:

- **Несколько баз знаний** — отдельная коллекция под каждого пользователя или проект.
- **OCR** (например, через Tesseract) для сканов.
- **Ответы с указанием точного места** в длинном документе — сейчас показывается страница/абзац, можно докрутить до цитаты.
- **Авторизацию** и разделение документов по доступам.
- **Веб-версию без локальной установки** — тот же код легко поднять как сервис, потому что RAG-логика отделена от интерфейса.
